# Reacting to early odometer requests
[Link to linear project](https://linear.app/electriccarscheme/project/reacting-to-early-odometer-requests-6cee08374f1f/overview)

## Figure out what's going on

### Current timeline
- 1st: Autosubmission created for everyone
- 21st: Email reminder sent out
- 27th: Email reminder sent out
- 31st/1st: Report generated
- 5th: Report sent

### Problem
Late manual submissions are being treated like early submissions - creating tiny
deltas, causing min charges (VERY BAD!)
- December autosubmission (generated on 1st Dec, estimating 31st Dec odometer
  reading) is 1000mi
- Customer submits "December" reading in January (e.g 2nd Jan) at 1010mi
- 31st January: reading from 2nd January is used as today's value - 1010mi,
  instead of 2000mi
- January's mileage is calculated as 10mi, instead of the real 1000mi
- Poor experience for customer, unrealised revenue for ECS

### Acceptance criteria
- Email on 21st
  - `Customer.where(last_submission_at <= 12th).send_email`
  - More than 8 days ago
- Email on 27th
  - `Customer.where(last_submission_at <= 18th).send_email`
  - More than 8 days ago
- Regenerate autosubmission
  - `if Customer.submits_on <= 18th then regenerate autosubmission`

### Questions
- Do we need to do autosubmissions for every manual submission? i.e. Is there
any point in autosubmitting before the 19th? Is there even any benefit to not
running daily?
- ***#person/stefan: run daily - probably easiest***
- *Does a submission that affects the 21st, make a difference to the 27th?*
  - ***No***
- *How adjustable are the cutoff points - front-end-adjustable,
  console-adjustable, hard-coded?*
  - ***Hard-coded***

## Figure out how to do it

### Emails
I'm seeing three options for the date-of-last-reading filter:
- By date for each email
```ruby
  # 21st email
  .where(last_reading_on <= 12th)
  # 27th email
  .where(last_reading_on <= 19th)
```
- By days for each email
```ruby
  # 21st email
  .where(last_reading_on <= 9.days.ago)
  # 27th email
  .where(last_reading_on <= 9.days.ago)
```
- By days globally
```ruby
  REMINDER_BUFFER = 9
  # 21st email
  .where(last_reading_on <= REMINDER_BUFFER.days.ago)
  # 27th email
  .where(last_reading_on <= REMINDER_BUFFER.days.ago)
```

Hard code the dates !!

```ruby
# app/jobs/charge_scheme/odometer_readings_reminder_job.rb
# CURRENT
def charge_order
  Dependencies['models.charge_orders']
    .status_active
    .live_on(Date.current)
    .left_outer_joins(:odometer_readings_real_this_month)
    .where(odometer_readings_real_this_month: { id: nil })
end
```

### Autosubmission
This is the autosubmission query
```ruby

# app/jobs/charge_scheme/creeate_auto_odo_readings_job.rb
def charge_orders(date)
  # We want auto submissions where the order has an initial reading
  # and does not have a reading for the month, except for the initial reading.
  Dependencies['models.charge_orders']
    .auto_odometer_submit_status_opted_in
    .live_on(date)
    .joins(:odometer_reading_initial)
    .joins(
      ApplicationRecord.sanitize_sql_array(
        [
          "LEFT OUTER JOIN odometer_readings AS month_readings ON
                month_readings.charge_order_id = charge_scheme_charge_orders.id AND
                month_readings.reading_type <> ? AND
                month_readings.day BETWEEN ? AND ?",
          Dependencies['models.odometer_readings'].reading_types[:initial],
          date.beginning_of_month,
          date.end_of_month
        ]
      )
    )
    .where('month_readings.id IS NULL')
    .distinct
end
```
